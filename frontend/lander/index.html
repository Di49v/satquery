Project Overview & Assessment

The National Earth Observation Portal is a secure, multi-tier spatial data infrastructure project developed to facilitate advanced geographical analysis, environmental monitoring, and national planning. It provides varying levels of access to high-resolution optical imagery, live multi-spectral telemetry (including NASA GIBS overlays for NDVI and Thermal), and advanced SQL-based querying capabilities.

Authorized personnel and institutional researchers can assess environmental trends, execute dynamic data plotting, and perform multispectral comparative analyses directly within the browser environment.

REST API Documentation (v1.2) - National Earth Observation System ×

This document outlines the REST API endpoints available for integrating the National Earth Observation Portal's AI and data retrieval capabilities into authorized governmental applications.

1. Authentication & Access

Access to all endpoints is strictly authenticated. Requests must include a standard Authorization header with a Bearer Token provided by the Centralized Government SSO identity provider.

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Rate Limits: Automated queries are rate-limited to 50 requests per minute per authenticated nodal agency. Exceeding this limit will trigger automated IP suspension and logging in the central security audit.

2. Core Endpoints

2.1 Spatial Parameter Prediction (AI Model)

Predicts short-term environmental and telemetry trends using historical multispectral data processed through our internal machine learning models.

  • Endpoint: POST /api/v1/spatial/predict
  • Content-Type: application/json

Request Payload:

{
  "coordinates": {
    "lat": 31.6340,
    "lon": 74.8723
  },
  "model": "NDVI_TREND",
  "forecast_days": 7
}

Success Response (200 OK):

{
  "status": "success",
  "data": {
    "confidence_matrix": 0.89,
    "predictions": [
      {"date": "2026-08-28", "predicted_value": 0.45},
      {"date": "2026-08-29", "predicted_value": 0.46}
    ],
    "model_version": "v2.4-stable"
  }
}
2.2 Telemetry Crossmatch Retrieval

Retrieves synchronous comparative data across different optical and thermal sensors for a specified region or coordinate set.

  • Endpoint: GET /api/v1/analysis/crossmatch

Example Request:

GET /api/v1/analysis/crossmatch?region=Amritsar&sensors=thermal,ndvi
Webportal Architecture & Component Guidelines ×

This document details the frontend architecture, mapping engines, and operational segregation of the Earth Observation Portal.

1. Dual-Portal System Architecture

To comply with data security and segregation mandates, the system operates two distinct environments utilizing a shared backend infrastructure but completely isolated frontend feature flags and routing.

  • Institutional Research Portal (Tier-1): Designed for academia. Provides read-only access to basic OSM Vector mapping, historical data arrays, and limited metadata export. Live high-resolution telemetry is disabled.
  • Government Administrative Portal (Tier-2): Requires high-level clearance. Features live NASA GIBS telemetry overlays (Night Lights, Thermal LST), confidential metric computation, dynamic plotting, and full access to the Data Query Interface (DQI).

2. Mapping Engine (Leaflet) Integration

The visual component relies heavily on customized Leaflet.js instances. Standard controls are overridden to match the strict, minimalist UI requirements.

  • Base Maps: OpenStreetMap (OSM) and Carto Light for infrastructure reference.
  • Live Telemetry (NASA GIBS): Layers such as MODIS NDVI, MODIS Land Surface Temp, and VIIRS Day/Night Band are integrated using WMTS endpoints.

3. Dynamic Analysis & Plotting

Integrated data plotting allows real-time visualization of either map-selected environmental data or SQL DQI result sets. It utilizes Chart.js for rendering responsive line, bar, and scatter plots.

SQL Database Implementation Proposal ×

PROPOSAL FOR SPATIAL DATA QUERY INTERFACE (DQI)

Document Ref: GOV-RS-SQL-0926 | Status: APPROVED

1. Executive Summary

This proposal outlines the structure and usage syntax for the Data Query Interface (DQI) embedded within the Government Administrative Portal. The DQI is designed to provide analysts with terminal-like SQL access to live and historical telemetry records without requiring direct database management access.

2. Supported Query Syntax

The custom SQL parser implemented in the portal supports the following subset of standard SQL operations tailored for security and performance:

  • SELECT statements: Specifying columns or using wildcard (*).
  • FROM clause: Targeting telemetry or bookmarks tables.
  • WHERE clauses: Supporting standard comparison operators.

Example Approved Queries:

SELECT * FROM telemetry WHERE region = 'Amritsar';
SELECT id, sensor, elevation, temp FROM telemetry WHERE status = 'ACTIVE';
SELECT region, timestamp, temp FROM telemetry WHERE temp > 35;

3. Data Export & Integration

The DQI module integrates directly with the Dynamic Analysis engine. Results from any valid SQL query can be instantly piped into the charting tool for visualization, or exported locally as CSV, JSON, HTML, or secure PDF reports for departmental filing.
